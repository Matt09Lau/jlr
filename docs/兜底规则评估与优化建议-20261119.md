## 一、规则目标与定位（先对齐"兜底到底是什么"）

| 维度 | 定义 |
|---|---|
| 业务目标 | 对**低频、长尾、安全关键**配件，当模型算力不足（历史需求稀疏）时，给一个**最低保障数量 V**，避免因预测缺数据而漏备货。 |
| 定位 | 兜底是"下限抬升"，**不是替换模型结果**：仅当风控后目标 `S1 < V` 才触发；`S2=max(S1,V)`、`R2=ceil(0.75V)`、`B低2=ceil(0.5V)`、`B高2=max(S1,V)`。 |
| 适用范围 | **仅 PO 采购建储**；STO 不应用采购兜底（需求 13.6、字段表 16~22 均注明"仅 PO"）。 |
| 输出 | 命中后写 `兜底值 floor`、`是否应用 floorApplied`、`兜底原因 floorReason`、`兜底后四项` 至建储结果表，供追溯。 |
| 优先级关系 | **不建储（直供经销商）优先于兜底**：采购类别=D 直供经销商最终四项=0，兜底/人工均不得抬高。 |
| 阈值性质 | 截图已注明"价格、频次、销量分档需做数据分析后决定怎么调"——当前所有阈值均为**待校准的临时值**，应参数化，禁止硬编码。 |

> 一句话：兜底 = PO 场景下，对指定类别配件在 `S1<V` 时按下限 V 抬升库存的一组**可配置风险保障规则**。

## 三、规则要素梳理（当前设计）

| 要素 | 现状 |
|---|---|
| 规则目标 | 低频/长尾/安全件的最低保障；仅 PO；`S1<V` 才触发。 |
| 触发条件 | C：ABC=C + 销量<8；D：ABC=D（实现却加了销量<8）；S/E：ABC∈{S1,S2,S3,E} + 频次≥1；S0：ABC=S0 + 无法行驶。 |
| 优先级 | 组级：C(1) → D(2) → S/E(3) → S0(4)；组内按 priority 升序。 |
| 匹配顺序 | 组优先级升序 → 组内分档优先级升序 → **首个命中即生效**（`matchGroup`）。 |
| 默认处理 | 无任何规则命中 → 不触发兜底 → 用风控后值（需求"S1<V才触发"，未命中 V/原因为空）。 |
| 边界场景 | 价格空/≤0.01 单独成档；频次 1~2 与 ≥3 衔接；无销量字段统一视为"不满足 <8"；不建储件四项归零。 |

## 四、问题清单（不一致 / 遗漏 / 风险，按严重度分级）

### P0 — 会直接导致错误结果，须优先修复

**P0-1　C/D 规则缺少 ABC 分类条件，造成跨类别错误拦截（最严重）**
- `seedGroups()` 中 C 组每条规则条件只有 `fallback_c_week_avg<8` + 价格档，**没有 `abcClassification=C`**；D 组同样没有 `abcClassification=D`。
- 引擎按"组优先级升序、首个命中生效"运行，且 `matchGroup(group, mat)` **不检查组级条件**（组只有 description 文本，无 group-level conditions）。
- 后果：任意 ABC 分类的配件，只要周均销量<8 且价格命中档位，都会在第 1 组（C 类）被命中并拿到 C 类兜底值。D 组永远抢不到；S/E、S0 组也会被 C 组前置拦截——例如一个 S0 安全件若价格低、周均<8，会先命中 C 组，永远到不了 S0 组。
- 各类别"互斥"的假设在数据层面并未落地，组优先级形同虚设。

**P0-2　D 类价格分档缺失 4 档**
- `cTiers.slice(0,4)` 只保留 ≤0.01、≤2、≤20、≤60 四档，>60~200、200~500、500~2000、>2000 四档缺失。
- 后果：价格 >60 的 D 类配件无任何 D 档规则命中；叠加 P0-1，可能错误落入 C 组拿 C 值（C 组有全 8 档）。

**P0-3　"月均销量<8" 被实现为 "兜底C类周均销量<8"（口径错配）**
- 截图与需求均为"月均销量"（对应 `demand_month_avg_3m` 近3月月均销量），实现用 `fallback_c_week_avg`（周均）。
- 月均与周均是不同统计量，同一阈值 8 的业务含义完全不同。需求文档特别注明"不沿用后部摘要的'周均销量<2'"，说明该口径已被反复改动，属高风险字段。

### P1 — 设计遗漏与逻辑风险

**P1-1　D 类被额外加了销量门槛**：截图与需求中 D 类只有 `ABC=D`，无销量条件；实现强行套 `fallback_c_week_avg<8`，缩小了 D 类兜底范围。需确认是否有意。

**P1-2　A/B 类配件无兜底**：ABC 枚举含 A、B，但四个场景组均未覆盖。A/B 通常为高价值核心件，是否不兜底需确认。

**P1-3　S/E 频次=0 无兜底**：条件要求"频次≥1"，全新件/长尾件（频次 0）不命中 S/E 组；若其 ABC 为 S1-S3/E，则完全没有兜底保障。

**P1-4　S0 且"无法行驶=否"无兜底**：能正常行驶的 S0 件无规则覆盖。

**P1-5　无"未命中"监控**：所有规则都不命中时静默走风控值，缺少标记/告警，无法识别漏网件（A/B、频次0 的 S/E、S0 可行驶件等）。

**P1-6　组级 `enabled` 未参与匹配**：`matchGroup` 只判断 `rule.enabled`，不判断 `group.enabled`。停用整组后本地测试仍可能命中其规则；生产引擎是否跳过停用组需明确并统一。

### P2 — 可维护性与数据质量风险

**P2-1　"0.01<价格≤2 → V=50" 是异常尖峰**：价档单调性被破坏（空/≤0.01→5，稍贵→50，再贵→10…）。三方数值一致，但仍应从业务与数据分布上复核 50 是否笔误。

**P2-2　优先级无间隔、复制功能会制造重复优先级**：组/档优先级用 1/2/3/4、1..8 连续值，插入需整体重排；"复制组/复制规则"自动赋 `max+1`，易产生同优先级使顺序不确定。建议改为 10/20/30 步长并强制唯一。

**P2-3　OR 拆分依赖数组稳定排序**：C 类首档"空或≤0.01"被拆成两条同 priority 规则（`C_PRICE_1_0`/`C_PRICE_1_1`），靠"相同优先级按声明顺序首个命中"生效，依赖 `Array.sort` 稳定性，脆弱且难维护。

**P2-4　保存规则无冲突校验**：仅校验"名称/兜底值非负/有条件"，未校验价格区间重叠或留空、同组优先级重复、ABC 条件遗漏。配置错误无法在保存期拦截。

**P2-5　字段代理口径未在配置层表达**："近一年频次"用 `positive_order_line_cnt_12m_all`（全局正订单行数）代理；注册表同时存在 `..._12m`（本仓）与 `..._12m_all`（全局），用哪个直接决定兜底范围，需业务确认并固化。

**P2-6　配置页与结果计算脱节**：前端"兜底规则配置"与"建储结果计算"是两套独立演示数据，改规则不会重算结果（文档已声明为演示）。上线前必须由后端计算引擎实时读取规则并落地留痕。

## 五、优化后的规则结构

### 5.1 分层模型：场景组（适用范围）＋ 分档规则（判定与取值）

```
规则组 = 适用门槛（ABC分类 + 指标门槛，均为组级 AND 前置条件，必填）
       └─ 分档规则* = 分档条件（组内按优先级，首个命中）+ 兜底值 V + 兜底原因
全局前置：建储类型 = PO；非"不建储"件
```

**关键改造**：把 ABC 分类提升为**组级前置条件**（数据模型新增 group-level conditions），从根上杜绝 P0-1；若暂不能改模型，则必须在每条分档规则里补齐 ABC 条件，并加保存校验。

### 5.2 建议的场景组定义（优先级按"安全/关键度 + 互斥"重排）

| 组 | 场景 | 组级前置条件(AND) | 分档规则 | 建议组优先级 |
|---|---|---|---|---|
| G0 | 不建储拦截（前置，非兜底） | 采购类别=D（直供经销商） | 四项=0，流程终止 | 最高（先于兜底） |
| G1 | S0 安全件兜底 | ABC=S0 **且** 无法行驶=是 | V=1 | 1（安全件优先） |
| G2 | S/E 卖一补一兜底 | ABC∈{S1,S2,S3,E} **且** 近一年频次≥1 | 频次≥3→3；1~2→2 | 2 |
| G3 | C 类低频兜底 | ABC=C **且** 月均销量<8 | 按本组价格分档 | 3 |
| G4 | D 类兜底 | ABC=D（销量门槛待确认 Q1） | 按本组价格分档 | 4 |
| G5 | 默认（未命中） | 以上均不命中 | 不触发兜底，用风控值，记"未命中"标记 | 兜底 |

> 各组因带 ABC 条件而互斥，组间顺序主要影响冲突兜底与性能；把安全件 S0 提到最前，符合"安全关键优先"原则，也避免被 C 组拦截。

### 5.3 价格分档表（每组一份，杜绝 D 类漏档）

|  seq  | 条件（左开右闭，NULL 单独处理） | V(件) | 状态 |
|---|---|---|---|
| 1 | 销售价 IS NULL 或 ≤0.01 | 5 | 待复核 Q5 |
| 2 | 0.01 < 销售价 ≤ 2 | 50 | **待复核 Q5（异常尖峰）** |
| 3 | 2 < 销售价 ≤ 20 | 10 | |
| 4 | 20 < 销售价 ≤ 60 | 8 | |
| 5 | 60 < 销售价 ≤ 200 | 6 | |
| 6 | 200 < 销售价 ≤ 500 | 5 | |
| 7 | 500 < 销售价 ≤ 2000 | 4 | |
| 8 | 销售价 > 2000 | 3 | |

价格分档阈值全部参数化，C 组与 D 组各自持有一份（默认内容相同、对象独立），改造后 D 类不可能再漏档，且改本组价档不影响他组。

> 注：本节为设计基线。早期建议"C/D 共用一张唯一数据源表"，后按业务要求改为**组内自主分档**（各组分档彼此隔离），以第十一节的最新实现为准。

## 六、判定流程（建议）

```
输入：配件特征(ABC、销售价、无法行驶、采购类别、近一年频次、月均销量…) + 建储类型 + 风控后 S1/R1/B低/B高

1. 建储类型 = STO ?  → 不应用兜底，直接返回风控值，结束
2. 采购类别 = D（直供经销商）? → 不建储：四项=0，结束（兜底/人工不得抬高）
3. 按组优先级依次匹配，首个命中即停：
     G1  ABC=S0 且 无法行驶=是        → V=1，原因"S0安全件兜底"
     G2  ABC∈{S1,S2,S3,E} 且 频次≥1    → V = (频次≥3 ? 3 : 2)，原因"卖一补一兜底"
     G3  ABC=C 且 月均销量<8           → V=价格分档表(销售价)，原因"C类低频兜底"
     G4  ABC=D [且 月均销量<8? 待确认] → V=价格分档表(销售价)，原因"D类兜底"
4. 未命中任何组 → 不触发兜底：floor/原因留空，用风控值；打"未命中兜底"标记供监控
5. 命中候选 V 后，仅当 S1 < V 才真正应用：
     floorApplied=是, floor=V, floorReason=命中原因
     S2=max(S1,V); R2=ceil(0.75V); B低2=ceil(0.5V); B高2=max(S1,V)
   否则 S1≥V：各兜底后字段回填风控值/原线，V 与原因留空
6. 人工调整：仅可覆盖四项数值；不建储件不可调；原因必填留痕
7. 输出最终四项
```

**关键约束（写进引擎，不可仅靠约定）**
- 组级条件为 AND 前置，分档条件组内 OR/AND 明确；
- 同优先级必须唯一，匹配顺序确定；
- 字段值为 NULL 统一视为"不满足该条件"（避免误命中低/高档）；
- 不建储判定、STO 判定必须前置于兜底匹配；
- 命中后原因文案随规则落库，保证可追溯。

## 七、兜底策略与例外处理

| 场景/例外 | 建议处理 |
|---|---|
| 不建储（直供经销商） | 前置拦截，四项=0，兜底与人工均不得抬高（需求明文）。 |
| STO 调拨 | 全程不应用采购兜底。 |
| 安全件 S0（无法行驶） | 最高优先级、固定 V=1、独立原因；建议单独监控命中率。 |
| 价格空 / 负数 | 空值走首档并单独标记数据质量告警；负数视为异常，不命中任何价档并告警。 |
| 极低价值件（0.01~2 元档 V=50） | 复核 50 的业务含义；若为笔误按数据分析结果修正并留版本记录。 |
| 频次=0 的 S/E 件、可行驶的 S0 件、A/B 类 | 当前无兜底；确认是否新增"默认最低保障"规则，或明确"不兜底"并纳入未命中监控。 |
| 销量/价格字段缺失 | NULL 不命中门槛条件 → 不触发兜底；在大盘打标，避免脏数据静默漏备。 |
| 兜底值异常大 | 为 V 设置合理上限与告警（如超过配置阈值需二次确认），防止脏价档抬高库存。 |
| 人工兜底 | 对未命中件允许计划员手工指定兜底值与原因，独立于自动规则并留痕。 |

## 八、可维护性改进建议

1. **阈值参数化 + 版本化**：价格档边界、V 值、销量门槛、频次档全部入配置表并记录版本，禁止散落在代码常量里（截图已声明阈值待数据分析）。
2. **优先级步长化**：组/档优先级按 10/20/30 分配；"复制组/规则"生成新优先级时做唯一性校验并提示重排。
3. **保存期校验**：价格区间连续性/不重叠、同组优先级唯一、ABC 条件非空、V 上限、字段支持的运算符合法。
4. **取消脆弱的 OR 拆分**：条件模型原生支持组内 OR 分支（如"空 OR ≤0.01"作为一个分档规则），去掉依赖数组顺序的拆分技巧。
5. **规则—结果强绑定**：后端计算引擎实时读取生效规则版本，命中过程（命中组/档、候选 V、S1、是否应用、原因）全量留痕，配置页提供"试算/回放"能力。
6. **测试补强**：当前 `tests/` 无兜底匹配用例，建议新增覆盖——ABC 条件缺失拦截、D 类全 8 档、月均口径、S0 优先级、NULL 字段、不建储覆盖、STO 不兜底、优先级冲突等。

### 11.1 分层结构与 4 项示例数据

| 层 | 配置对象 | 说明 |
|---|---|---|
| 第一层 | 规则组的**组级适用范围 scope**（AND） | 必须含 ABC 分类条件，否则保存时拦截；可按仓库编码、销量门槛等追加条件 |
| 第二层 | **本组自己的条件分档** `tiers` | 每条档位 = 若干条件（字段 + 操作符 + 值，AND/OR）+ 兜底值 V；每组独立一份，无模式之分 |

首次进入展示的 4 项示例（优先级 10/20/30/40，名称均带「（示例）」）：

| 组 | 优先级 | 组级适用范围（AND） | 示例分档与 V | 销售价分档？ |
|---|---|---|---|---|
| S0 类兜底（示例） | 10 | ABC=S0 且 无法行驶=是 | 固定 V=1 | 否 |
| S/E 类兜底（示例） | 20 | ABC∈S1/S2/S3/E 且 近一年频次≥1 | 频次≥3→V=3；1~2→V=2 | 否 |

C/D 的 8 档价档是**普通销售价条件档位**（`salesPrice` + `IS_NULL`/`GT`/`LE`），非专门价格分档机制，各组独立持有互不影响。

### 11.2 组内自定义分档能力

在规则组详情内编辑**本组分档**，支持：
- 增删改档位、配置条件字段（配件主数据 19 个 + 仓库主数据 1 个（仓库编码）+ 指标宽表 16 个 = 36 个可配置字段），操作符与值，AND/OR 逻辑，兜底值 V、启停、上移/下移、复制；
- 新建档位默认**无条件**（在本组适用范围内默认命中），不预设任何价档；档位不再配置"名称"，以必填的兜底原因作为说明；
