# 库存策略参数与备货规则页面设计需求说明

面向产品 开发 测试和实施人员

版本日期 2026年10月23日    需求基线 第6版计算方案与最新确认页面

本需求覆盖库存策略参数下的8个菜单，以及全局参数和备货规则，共10个页面。目标是让计划人员能够按采购或调拨场景维护参数，生成可追溯的目标库存与再订购点，并通过审批和风控约束人工干预。开发人员据此实现页面、接口与计算取值，测试人员据此准备主数据、覆盖正常及异常路径。

# 1 业务背景与需求目标

中心仓通过采购为全国或区域仓备货，采购到货周期长、需求波动大，库存不足会影响配件供应，库存过高又造成资金和仓储占用。区域仓通过STO调拨满足本地需求，运输提前期和区域预测不同，不能直接照搬采购参数。

因此，将参数分成配件专属配置、分类通用配置和全局默认值三个层次。专属配置解决重点配件差异，分类规则降低维护工作量，全局参数保证未维护时仍有明确取值。所有参数按统一来源和版本参与计算，避免同一指标在多个页面重复计算或口径不一致。

| 业务问题 | 对应解决方式 | 形成的结果 |
|---|---|---|
| 不同补货场景被混用 | 目标满足率、周期、增储、风控按PO/STO分别维护 | 采购与调拨互不串用配置 |
| 计划员无法逐件维护全部参数 | 配件优先、分类其次、全局兜底 | 重点精细化维护，普通件批量覆盖 |
| 促销或供应不稳定需要临时多备货 | 增储天数带有效期并按身份审批 | 临时需求有依据，过期不继续影响计算 |
| 某些区域不应备某配件 | 配件与仓库独立维护允许/禁止及原因 | 控制STO建储范围，减少重复库存 |
| 模型结果偏高或低且原因难查 | 展示初始、风控、兜底和人工调整结果及来源 | 定位偏差并保留调整理由和前后值 |

## 1.1 术语说明

| 术语 | 业务含义 |
|---|---|
| PO建储 | 面向采购补货的库存目标计算，通常服务于中心仓。 |
| STO建储 | 面向仓间调拨补货的库存目标计算，按配件与建储仓库生成结果。 |
| LT | 提前期，单位天；采购LT为采购到货时间，库间LT为发货仓至收货仓的运输时间。 |
| 目标库存 S | 补货希望达到的库存水平，不等于本次建议采购或调拨数量。 |
| 再订购点 R | 用于判断补货触发的库存水平；不是最低风控线。 |
| 计划周期 P | 规划或补货检查周期，延长周期通常意味着需要覆盖更长时间需求。 |
| 服务水平 z | 安全库存计算中的标准正态分位数；目标满足率95%对应z约1.644854。 |
| 风控上下限 | 限制模型库存水平的边界，由历史销量、覆盖期、系数形成。 |
| 兜底 | PO低频等场景的最低保障数量；不等同全局参数默认取值。 |
| 建储日期 | 结果实际服务的业务日期；与运行计算的日期、审批日期分别存储。 |

# 2 通用页面和数据规则

## 2.1 字段表阅读方式

“必填”区分用户必填、条件必填和系统生成。名称、服务水平、审批状态等只读字段不要求用户导入。字段类型为业务类型，不强制数据库字段长度；编码统一按字符串传输，不能丢失前导零。所有列表单元格只读，详情只读，修改通过表单保存。

各字段表按业务字段在现行列表中的顺序列出，不包含勾选框、操作列。字段英文名沿用现行页面识别键；全局参数英文名为建议开发命名，正式接口映射由技术设计统一，不表示已核实后台物理字段。序号、中文名、英文名分别成列。新增可选但修改不可改的字段为业务唯一键；改键应新增另一条配置，不能改写已关联的历史记录。

### 2.1.1 唯一键说明

业务唯一键用于判断是否重复配置，系统主键用于识别记录与关联历史，两者分开。所有业务编码以有效主数据编码比较，名称不入键；同键修改配置值不生成另一条当前配置。数据库主键建议统一使用不可变id，具体类型由技术设计确定，不在页面展示。以下为正式开发约束建议，增储版本和结果批次需随后台模型落地。

| 模块 | 业务唯一键 | 重复及历史处理 |
|---|---|---|
| 采购LT | 配件号 part | 每个有效最新配件仅一条当前配置。 |
| 目标满足率 | 建储类型 buildType＋类型 type＋仓库 wh＋配件 part 或ABC abc | 配件型用part，分类型用abc；非适用项为空。两类分别建立条件唯一约束，避免数据库NULL导致重复。 |
| 库间LT | 发货仓 shipWh＋收货仓 receiveWh | 有向路线；A至B与B至A为不同键。 |
| 增储天数 | 建储类型 buildType＋配件 part＋仓库 wh；申请另用独立申请ID | 同维度允许批准历史与变更申请共存；当前批准版本与在途申请分开。批准配置有效区间不得冲突，同维度在途申请禁止重复提交；申请ID和版本号作审计关联。 |
| 计划周期 | 建储类型 buildType＋类型 type＋配件 part 或ABC abc | 不含仓库；配件型和分类型分别条件唯一。 |
| 配件风控线 | 建储类型 buildType＋配件 part＋仓库 wh | 四项风控参数不入键，同键只保留一组当前参数。 |
| 配件多分类风控线 | 建储类型 buildType＋仓库 wh＋ABC abc＋XYZ xyz＋体积 volume＋金额 amount | 完整组合唯一，各分类必填，不将空值当通配。 |
| 全局参数 | 参数代码 parameterCode | PARM01至PARM10分别唯一；参数描述、值、备注不入键。 |
| 备货规则 | 配件号 code＋仓库编码 whCode | 允许或禁止及原因不入键；同配件可在不同仓库分别配置。 |
| 建储水位线结果 | 批次ID batchId＋建储类型 buildType＋配件 part＋建储仓库 wh＋建储日期 useDate | 同批次同维度仅一条；YYYYWW版本号不足以区分重算。batchId为建议后台字段。STO不同建储日期分别保留，重算建立新批次，不覆盖历史。 |

新增、修改及导入须同时校验库内和文件内唯一性；修改时排除当前记录自身。名称相同或参数值相同不代表键相同。后台以唯一约束及事务处理并发重复，失败返回冲突编码与行号。增储历史版本按配置ID＋版本号唯一，审批日志按申请ID关联，不以申请人或状态替代主键。

## 2.3 查询列表与导出

• 查询条件紧凑横向排列，空间不足换行。默认展示前3个常用条件，其余展开；查询条件多项取交集，重置同时清空列头筛选并回到第一页。

• 编码和名称按页面规则检索；数字区间包含上下界，开始值不得大于结束值。日期区间起止可单独填写，起止均填时须顺序正确。

• 导出为当前类型、当前筛选命中的全部记录，不仅当前页；全量导出忽略查询条件但仍受当前建储类型和数据权限限制。列表与导出字段顺序一致。

• PO/STO切换时清空不适用筛选、勾选和弹窗。库存策略参数菜单无列设置按钮；导出与全量导出使用相同按钮样式。

查询匹配规范：策略配置页配件、仓库、类型、分类等下拉项精确匹配，配件名称、计划员等文本包含匹配；数字区间上下界均包含。结果页版本号、配件号和仓库编码支持文本包含查询。备货规则仓库编码精确匹配，仓库名称、配件名称包含匹配，配件号忽略大小写包含匹配；全局参数代码忽略大小写包含匹配，名称包含匹配、字段类型精确匹配。日期与审批期限统一按Asia/Shanghai业务日判断，不能因浏览器或服务器时区不同跨日。

## 2.4 导入通用流程

下载模板 → 填写编码和维护字段 → 上传 → 解析与逐行校验 → 展示成功行数及错误清单 → 无错误时确认提交。当前演示采用CSV；正式Excel支持范围、文件大小和条数上限由接口设计给出。

错误清单至少包含文件行号、字段名、原值、错误原因；例如“第5行 仓库编码 W999 不存在于仓库主数据”。发现表头重复、未知列、缺失必填列、引号不闭合或整文件无有效记录时阻止提交。

配置页面当前演示为新增型导入：库内同唯一键报重复，不自动覆盖。第6版采购LT和库间LT描述“同键更新”，需在正式接口支持时明确使用更新模式并显示新增/更新预览；不能在未提示用户时静默覆盖。该导入模式差异列入第14章衔接事项。增储导入只产生待审批申请，不允许直接导入为审批通过。

# 3 参数如何共同形成建储结果

以一次建储为主线：先确定配件和建储仓库及业务日期，再从指标表和预测结果取需求输入，按优先级匹配参数，计算初始库存，执行风控和采购兜底，最后允许授权人员人工调整。下游使用最终调整后值，不能把初始目标误当最终目标。

| 步骤 | PO采购建储 | STO调拨建储 |
|---|---|---|
| 范围 | 最新配件；建储仓库取配件主数据收货仓 | 最新配件与允许备货仓库组合；发货仓取配件主数据收货仓 |
| 预测与指标 | 下月人工调整月预测；配件维度近3月月均及近6月标准差 | 目标周人工调整周预测；配件仓库维度近12周均及近8周标准差；风控内部仍取近8周均值 |
| 提前期 | 配件采购LT配置；未命中PARM01 | 发货仓至建储仓库库间LT配置；未命中PARM02 |
| 保障与周期 | PO目标满足率、计划周期及增储 | STO目标满足率、计划周期及增储 |
| 风控 | PO配件风控线优先，其次多分类，再全局 | STO配件风控线优先，其次多分类，再全局 |
| 最终处理 | 风控后可触发采购兜底，再判断不建储及人工调整 | 不应用采购兜底；禁止备货不建储；允许人工调整四项 |

## 3.1 匹配优先级

| 参数 | 匹配规则 |
|---|---|
| 采购LT | 按最新配件匹配；手工方式取人工LT，分位数方式取对应分位数；无配置取PARM01。配置存在但所选分位数缺失不能当0，按计算异常处理并提示来源。 |
| 目标满足率及服务水平 | 同建储类型：配件＋建储仓库 → 配件ABC＋建储仓库 → 全局PARM04与PARM05。必须成对同层取值；专属或分类配置中的z由满足率计算。 |
| 计划周期 | 同建储类型：配件配置 → 配件ABC分类配置 → PARM06。PO周期为枚举，STO为人工正整数；按最新确认的类型分维维护。 |
| 增储天数 | 同建储类型＋配件＋建储仓库，且已审批通过，生效日≤建储日期<失效日；匹配不到PARM03。审批中修改仍使用原已批准版本。 |
| 风控参数 | 同建储类型：配件＋仓库 → 仓库＋ABC＋XYZ＋体积＋金额分类组合 → PARM07至PARM10。四项作为一组命中，不能拼接不同层级的半组。 |
| 库间LT | 按发货仓→收货仓有向组合匹配，不互换方向；本文页面按仓间通用路线维护。第6版计算文字另含配件维度，衔接差异见第14章。 |

## 3.2 日期与当前生效天数

建储日期是参数适用日期。PO使用下月1日；STO本周建储使用当前日期加7天所在周的周一，下周建储使用当前日期加14天所在周的周一。增储有效期是半开区间，生效当天包含，失效当天排除。

当前生效天数只表示当前日期下已批准配置的有效天数，用于对比申请值。未审批的新申请无旧值时显示0；修改审批中且原批准配置当前有效时显示原值；原配置未到生效日或已失效时显示0。该字段不能直接供所有建储日期取值，计算批次必须独立匹配建储日期。页面不展示生效状态。

# 4 采购LT

## 4.1 场景与目的

配件供应商和运输路径不同，到货速度差异很大。若所有配件都用统一采购LT，会使长周期件缺货、短周期件积压。

允许计划员选人工维护或历史到货分位数；统计字段由系统每天计算，作为选择依据，不允许人工伪造样本。

场景示例：某配件历史到货中位数为30天，但供应中断后预计需60天，可切换为手工维护60天；恢复稳定后再选50分位数。

## 4.2 查询与数据维度

唯一维度：最新配件号。

# 7 增储天数

# 12 备货规则

## 12.1 场景与目的

同一配件并非每个区域都需要库存。如果仅按配件统一允许备货，可能让低需求区域重复占用库存，也难解释禁止备货的原因。

以配件＋仓库为最小单元分别设置允许或禁止，并维护原因。用于决定STO计算范围，不建立收货仓与发货仓的对应关系。

场景示例：配件A可在北京仓允许、广州仓禁止；批量修改北京仓一组配件的原因，不影响广州仓或其他配件。

## 12.2 查询与字段

菜单位于基础数据管理，库存策略参数下不再重复设置。查询为仓库编码、仓库名称、配件号、配件名称；展开备货标识。唯一维度为有效最新配件号＋仓库编码。仓库类型、ABC、XYZ不作为本页查询或展示字段。

| 序号 | 字段中文名 | 字段英文名 | 类型与单位 | 必填 | 新增与修改 | 取值及业务说明 |

## 12.4 校验与计算影响

• 配件和仓库均必填且存在有效主数据；备货标识必填且属于允许/禁止，备注去首尾空格后最多500字。

• 新增组合唯一；批量预览及文件内重复同配件同仓库时报错。批量设置至少选一条记录且至少选一种修改内容；整批先校验权限和版本。

• 禁止标识不代表删除主数据，不影响其他仓库允许状态，也不自动改写历史STO结果；后续STO计算排除禁止组合。若保留禁止组合说明行，最终四项为0并记不建储原因。

• 只存在一条当前配件仓库规则；本页没有“代收仓/发货仓/收货仓配对”的配置维度，不增加相关必填项。

## 13.1 场景与目的

计划人员需要知道某个结果为什么高、为什么低，以及是否因为缺配置而使用默认值。只展示最终库存无法定位参数或预测问题。

在一个入口切换PO/STO，依次展示基础信息、初始库存、风控、PO兜底、最终调整结果及输入参数来源，支持对实际四项结果人工修正并留痕。

场景示例：采购模型因月度预测增长得出较高目标，风控压到上限；若触发低频兜底再抬高，用户可清楚看到每一步，并在有依据时调整最终值。

## 13.2 查询和展示规则

• 默认PO视图；切换清空当前筛选、分页、选中及弹窗。PO57个业务字段，STO52个业务字段，列表、详情和导出一致。STO不展示近8周周均销量，但后台计算风控仍使用该指标。

• 常用查询：版本号、配件号、建储仓库编码；展开：每项取值来源、配件名称、ABC、计划员、建储日期起止、不建储原因。来源逐项独立选择配置表或全局参数，支持联合筛选。

• 目标库存突破风控线列头按是/否筛选；再订购点突破列头按突破最高风控线、突破最低风控线、否筛选。大于最高或小于最低才算突破，等于边界不突破。

• 突破风控的数值红色区分；使用全局参数的指标值及来源用橙色区分，配置表来源标签蓝色。每项按实际来源着色，不把整行标成全局来源。

• 风控、兜底各阶段值集中展示；预测值与预测日期相邻；其他参数放在后部。同版本STO默认按建储日期升序，版本默认新到旧，查询和导出沿用默认顺序。

• 不展示额外复杂超限条件或“突破风控线指标取自全局参数配置表来源”文案；无需用户判断颜色才能获得信息，导出保留具体方向和来源文字。

## 13.3 字段含义和必填约定

结果表“系统必需”指计算成功时由系统提供，不是用户填表；主数据名称、分类及日期按输入条件回填。不适用为空显示破折号，0表示真实零值。阶段值均只读；四项调整后字段在列表只读、在调整弹窗必填可改。异常结果不得用0冒充成功，具体异常存入计算日志或详情。

## 13.5 已确认计算公式

符号：F为PO月预测，W为STO周预测，M3为近3月月均，M8为近8周周均，σ6/σ8分别为对应月/周样本标准差；L为采购LT，l为库间LT，P为当前类型计划周期，D为命中增储天数，z为服务水平，a低/a高和k低/k高为四项风控参数。clamp(x,b低,b高)=max(b低,min(b高,x))。

| 环节 | 公式与处理 |
|---|---|
| PO 初始R0 | H=L+P+D；R0=F×H/30+z×σ6×√(H/30)。 |
| PO 初始S0 | S0=F×(2L+P+D)/30+z×σ6×√((2L+P+D)/30)。 |
| PO 风控线 | B低=(L+P+D+a低)/30×M3×k低；B高=(L+P+D+a高)/30×M3×k高。不额外乘3。 |
| PO 风控R1与S1 | R1=clamp(R0,B低,B高)。R0被风控时S1=min(R1+L/30×F,B高)；未被风控时S1=min(S0,B高)。 |
| PO 兜底 | 命中V且S1<V才触发：S2=max(S1,V)，R2=ceil(0.75V)，B低2=ceil(0.5V)，B高2=max(S1,V)。未触发各值回填风控或原线，V及原因为空。 |
| STO 初始R0 | h=l+P+D；R0=ceil(W×h/7+z×σ8×√(h/7))。 |
| STO 初始S0 | S0=W×(l+P+D+7)/7+z×σ8×√((l+P+D+7)/7)。 |
| STO 风控线 | B低=(l+P+D+a低)/7×M8×k低；B高=(l+P+D+a高)/7×2×M8×k高。M8不展示但仍是计算输入。 |
| STO 风控后 | R1=clamp(R0,B低,B高)；S1=min(S0,B高)，按专门计算章节不额外clamp到下限。 |
| 最终值 | PO人工值→兜底值→风控值；STO人工值→风控值。每个字段独立取首个非空；不建储四项最终值均0。 |

输入来自指标表和预测版本，不在结果页面重新统计。中间量不随意舍入；原文明确STO再订购点与采购兜底相关ceil时按向上取整执行。其他输出精度和最终取整尚需与计算接口统一，不能仅按页面两位显示精度截断内部计算值。EOQ本期不实现成本模型，STO按原文临时使用额外7天需求覆盖。
