## 2.1 PO 建储采购LT 调整

**依据**：需求清单"方案"列「采购LT配置」（序号 19）；前端设计稿 `inventory-strategy.js` 采购LT配置页、`inventory-results.js` PO 建储结果页。

### 2.1.1 取值逻辑调整

**核心逻辑（方案）**

- PO 建储的采购LT按优先级取值：① 配件与供应商关系中默认供应商的交付提前期（planned_deliv_time，系统同步）→ ② 采购LT配置页（人工配置 / 分位数）→ ③ 全局参数默认采购LT。
- 取值来源须可追溯，结果页逐行返回并展示来源。
- 适用范围：PO 建储采购LT取值与采购LT配置页；是否同步适用于 STO【待确认】。

**具体效果（前端）**

- 采购LT配置页唯一键为配件号；查询条件为配件号、配件名称、取值来源、计划员；列表字段依次为：配件号、配件名称、计划员、取值来源、人工配置LT、样本数、25分位数、50分位数、75分位数、95分位数、分位数最新计算日期、修改人名称、更新时间。
- "取值来源"下拉当前仅有两项：**人工配置、分位数**。选"人工配置"时填写人工配置LT；选"分位数"时填写样本数及各分位值；切换来源时清空不适用字段。
- 页面"配置说明"原文：取值来源选「人工配置」时填写人工配置LT；选「分位数」时填写样本数和各分位值。建储计算引擎按优先级取采购LT：① 配件与供应商关系（默认供应商，系统同步）→ ② 本页配置 → ③ 全局参数。分位数需样本数不少于 12；全局参数作为系统级兜底在独立页面维护。
- 校验：人工配置LT须为正数、最多两位小数；分位数方式样本数须 ≥ 12，不足时提示"该配件样本数不足 12，不能使用分位数方式，请改为人工配置"。
- 演示数据口径：计划员取"张计划/李计划"；样本数、25/50/75/95 分位数由系统计算展示，人工不可伪造。
- 差异【待确认】：方案"取值方式枚举新增系统同步"，但前端配置页把"系统同步"作为配件与供应商关系带来的**来源**、只在结果页体现，配置项本身仍为人工配置/分位数两项。系统同步是否需在配置页作为可选枚举，待业务确认。

### 2.1.2 PO 建储结果显示

**核心逻辑（方案）**

- 采购LT取值来源新增"系统同步"；取自配件与供应商关系表时来源显示"系统同步"。
- 筛选区提供"系统同步 / 配置表 / 全局参数"三个选项，结果按所选来源过滤。

**具体效果（前端）**

- PO 建储结果页字段"采购 LT取值来源"（purchaseSource）与"采购LT（天）"（purchaseDays）成对展示，来源实际出现三种值：**系统同步、配置表、全局参数**。
- 演示数据分布：有系统同步LT的配件来源为"系统同步"；无系统同步LT时部分取"配置表"（按配件序号）、其余取"全局参数"（默认 45 天，前端演示值；正式值以全局参数 PARM01 为准）。
- 其他参数（计划周期、增储、目标满足率、服务水平、风控系数等）同样带"取值来源"列，取值来自配置表或全局参数；使用全局参数来源的指标值及来源以橙色标识、配置表来源标签以蓝色标识，逐项着色而非整行着色。
- 结果按"采购LT取值来源"筛选；结果列与筛选选项与截图一致。
- 边界【待确认】：来源为空或出现未定义枚举时的展示与筛选行为。

### 2.1.3 异常、依赖与验收

- 异常边界【待确认】：同一配件多条"默认供应商=是"记录的取值；planned_deliv_time 为空或非正数时是否回退；系统同步触发时机/频率及是否覆盖人工值；调整后全局默认采购LT是否仍为 60；写入时点及失败处理。
- 依赖：配件与供应商关系表 planned_deliv_time 同步链路；配置页来源展示；全局参数已维护。
- 验收：按"配件号 + 默认供应商=是"命中时来源显示"系统同步"；优先级 系统同步 > 配置表 > 全局参数 正确；无命中取全局默认；结果列与筛选三选项齐全。

## 2.2 配件扩展属性

**依据**：需求清单"方案"列「配件扩展属性」（序号 11）；前端设计稿 `JLR_主数据前端设计稿.html` 配件扩展属性页（matExtColumns / matExtFilters）。

### 2.2.1 目标与适用范围

支持采购类别按映射规则显示，并可在页面编辑、手工录入采购类别。作用于配件扩展属性页面的采购类别字段。

### 2.2.2 核心逻辑（方案）

- 采购类别由 ipos 同步，源枚举 Y / IH / D。
- 显示映射：Y → CJLR国产，IH → CJLR自制，D → CJLR直供。
- 支持手工录入 JLRC国产、JLR进口。
- 下拉可选项 5 项：CJLR国产、CJLR自制、CJLR直供、JLRC国产、JLR进口。

### 2.2.3 具体效果（前端）

- 采购类别列以彩色标签展示，宽度 130，颜色映射：CJLR国产=绿、CJLR自制=蓝、CJLR直供=金、JLRC国产=青、JLR进口=紫；列支持按名称排序。
- 采购类别为可编辑下拉，选项即上述 5 项，并开启**手工录入**（freeInput）。
- 筛选区新增"采购类别"下拉筛选，选项同 5 项。
- 配件号列为链接列：**点击配件号弹出"配件详情"弹窗**（只读展示配件信息，含采购类别）；编辑入口为行操作列的"编辑"，打开编辑弹窗维护采购类别等可编辑字段。
- 差异【待确认】：方案"点击配件号打开编辑配件弹窗"，前端实际为"点击配件号打开详情弹窗、编辑走行操作列"。以哪一版为准需确认；当前按前端效果，两入口并存（详情弹窗可见、编辑弹窗可改）。

### 2.2.4 关键流程与规则

1. 在配件扩展属性列表点击配件号，打开详情弹窗查看；或点击行内"编辑"打开编辑弹窗。
2. 展开"采购类别"下拉，显示 5 个选项，亦可手工录入 JLRC国产 / JLR进口。
3. ipos 同步值 Y/IH/D 按映射显示为对应中文名称。
4. 点击"确定"保存，"取消"放弃。

### 2.2.5 数据、边界与验收

- 数据与接口：采购类别保留 ipos 同步来源 Y/IH/D 并按映射显示；枚举字典配置 5 项展示名与可选项。
- 边界【待确认】：保存写入显示名还是编码、是否回写 ipos；同步值非 Y/IH/D 的显示；手工录入值与同步值冲突及后续同步是否覆盖；为空时的必填校验；编辑权限与操作日志。
- 验收：Y/IH/D 分别显示为 CJLR国产/CJLR自制/CJLR直供；下拉含 5 项且可手工录入两项；点击配件号弹出详情弹窗、编辑入口可改并回显正确。

## 2.3 替代链

**依据**：需求清单"方案"列「替代链」（序号 12、13、14）及「替代链扩展属性」（序号 15、16，涉及"人工调整可采购件"，与本章相关）；前端设计稿 `JLR_主数据前端设计稿.html` 替代链页（replaceDef）、替代链扩展属性页（replaceExtDef）。

### 2.3.1 目标与适用范围

查询链上任一配件展示完整链条；链上区分 Suggest（未激活）与 Active（已激活）状态；调整"最新可采购件"取值。页面含筛选区（配件号、最新配件号）与列表（配件号、最新配件号、物料替代链、最新可采购件、人工调整可采购件、更新时间、操作）。

### 2.3.2 核心逻辑（方案）

- 完整链条：搜索链上任一配件均展示其所在整条链（如查 B 显示 A》B》C，而非仅 B》C）。
- 状态区分：新增 Suggest 状态，未激活节点也显示在链上，与 Active 以不同符号/样式区分。
- 最新可采购件：取消自动向上回溯上一级配件，只判断最末级配件；最末级无有效合同时该字段为空。有效合同判断：合同号（Purchasing Document）有效，当前日期大于 Date of Document 且小于 Valid to；Valid to 为空则一直有效。

### 2.3.3 具体效果（前端）

- "物料替代链"列以 from → to 逐段渲染：整链按 2~4 个配件组装，链上每个配件各生成一行。相邻段共用节点，起点只绘制一次。
- 状态以线段颜色和线型区分：**已激活（condition_type=ZSSA）为绿色实线**，**未激活为灰色虚线**；未激活节点以弱化样式显示，鼠标悬停提示"配件号（已激活/未激活）"。
- 前端合同判断口径：**Date of Document ≤ 当日，且 Valid to 为空或 ≥ 当日**（含边界）；无有效合同则"最新可采购件"为空，不再向上级回溯。与方案文字"大于 Date of Document 且小于 Valid to"存在边界差异【待确认】，以哪一版为准需业务确认。
- 替代链页数据来源为数据平台（Hive）同步，页面只读，不提供新增、删除、导入、导出；页面说明文案已明确上述口径。
- 替代链扩展属性页：仅"人工调整可采购件"可编辑（配件号、最新可采购件只读）；为空表示未做人工覆盖、按最新可采购件口径使用；支持逐条编辑与批量导入，更新后自动记录修改人与更新时间。
- 差异说明：需求清单"替代链扩展属性"要求"人工调整可采购件"校验存在于配件主数据，属独立模块事项【是否纳入本章待确认】。

### 2.3.4 关键流程、边界与验收

1. 输入配件号或最新配件号检索，返回包含该配件的完整链条。
2. 各节点按 Active/Suggest 以绿实线/灰虚线区分展示。
3. 最新可采购件：取最末级配件判断有效合同，有则显示、无则为空。
- 边界【待确认】：Suggest/Active 符号与图例规范；一条链多分支或配件属多条链的展示；Date of Document/Valid to 缺失或非法的处理；最末级无有效合同时为空的展示样式（留空/占位）；替代链与替代链扩展属性表历史残留数据的清理范围与责任方。
- 验收：查链上任一配件返回完整链条；Active/Suggest 可区分且未激活节点仍显示；最新可采购件仅依最末级有效合同判断、无则为空；合同日期判断口径明确后与前端一致。

## 2.4 批量搜索

**依据**：需求清单"方案"列「配件号、仓库编号支持批量搜索」（序号 22）；前端设计稿 `JLR_主数据前端设计稿.html`、`inventory-strategy.js`、`inventory-results.js` 的批量录入弹窗与解析逻辑（`parseBatchQuery` / `parseBatch` / `parseBatchCodes`）。

### 2.4.1 目标与适用范围

一次录入多个配件号或仓库编码检索并展示命中数量。**本次更新后，全系统所有含配件号/仓库编码查询的页面统一采用同一套"弹窗式批量录入"方案**（与配件扩展属性页一致），不再区分弹窗式与内联文本域式。

| 建储结果 | PO 建储结果 / STO 建储结果 | 配件号、建储仓库编码 |

### 2.4.2 核心逻辑（方案）

- 支持配件号、仓库编码批量搜索，结果列表展示命中记录数（"共 N 条"）。
- 分隔符支持换行、逗号、分号、Tab，并实时显示识别数量。
- **本次变更**：去掉双引号分隔符（双引号不再作为分隔符，按字面字符处理）；批量粘贴上限提升到 1000 个。

### 2.4.3 具体效果（前端）

- **统一弹窗式批量录入**：上表所有页面的配件号/仓库编码类筛选，均改为点击筛选按钮（显示已录入个数）弹出"批量录入弹窗"，不再有筛选框内联多行文本域。原内联文本域式（44px/192px 展开收起）已全部移除。
- 弹窗规格（全页面一致）：标题"批量录入 · {字段名}"，宽度 440（窄长），提示文案"支持换行、逗号、分号、Tab 分隔符粘贴，最多 1000 个，共识别 N 个"，主体为多行文本框（占位提示"每行一个或用逗号/分号/Tab分隔，支持批量粘贴，最多 1000 个"），底部按钮"清空 / 取消 / 确定（已录入 N 个）"，弹窗内不展示解析结果明细。
- 分隔符解析：换行、逗号（含中文逗号）、分号（含中文分号）、Tab；**不含双引号**；解析后去首尾空格、过滤空值，实时统计识别个数。
- 匹配规则：单值保持模糊匹配（与原文案一致）；多值批量时按"精确命中任一"匹配，并兼容字段值本身为逗号拼接串（如组内配件号）。
- 数量上限：提示与占位文案均标注"最多 1000 个"；实测粘贴 1000 行可全部识别。
- 搜索结果列表底部分页展示命中总数（"共 N 条"）。

### 2.4.4 关键流程、边界与验收

1. 在任一页面的配件号/仓库编码批量入口（筛选按钮）点击，弹出批量录入弹窗。
2. 粘贴或输入多个编码（换行/逗号/分号/Tab 分隔），弹窗实时显示识别数量。
3. 点击"确定"回填筛选条件并关闭弹窗；点击"搜索"返回所有匹配记录，结果底部展示"共 N 条"并分页。
- 边界【待确认】：空值、重复值处理（首尾空格已自动去除）；部分编码不存在时忽略还是提示；与其他筛选条件的 AND/OR 关系（现行为 AND 交集）；"导出/全量导出"是否作用于批量结果。
- 验收：全部页面配件号/仓库编码均为弹窗式、无内联文本域；弹窗文案无"双引号"、含"最多 1000 个"；双引号不做分隔符（`"LR001","LR002"` 识别为 2 个）；粘贴 1000 行识别为 1000 个；结果数量展示正确。
